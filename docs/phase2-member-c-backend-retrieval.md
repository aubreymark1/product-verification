# 第二阶段任务文档：成员 C

## 任务主题

商品事实、证据检索和后端数据服务：为个性化分析提供可过滤、可追溯、可验证的上下文。

## 本阶段目标

后端不再只按商品整体排序证据，而是能够根据用户需求字段检索相关商品事实和证据，并为 D 的分析引擎提供统一的结构化数据。

## 允许修改范围

- `backend/app/api/`
- `backend/app/database/`
- `backend/app/models/`
- `backend/app/schemas/`
- `backend/app/services/retrieval/`
- `backend/tests/`
- `data/real/` 和数据处理脚本

不得直接修改 `data/mock/` 结构，不得直接改动前端页面或 D 的分析算法。共享合同变更必须先与 D 和项目负责人确认。

## 具体任务

1. 建立商品事实和证据的 Pydantic 读取模型，兼容类目差异，避免写死具体商品字段。
2. 提供按 `product_id`、`category_id` 和需求字段检索事实/证据的内部服务。
3. 证据检索结果必须保留 `evidence_id`、来源类型、关联等级、可信度和原始来源信息。
4. 支持区分官方资料、专业测评、用户反馈和演示 Mock，供 D 处理证据优先级。
5. 完善购买渠道查询，数据为空时返回空列表，不在后端伪造渠道或价格。
6. 增加结果读取或恢复所需的后端能力，避免刷新或重新打开结果链接后只能显示空状态；具体路径先与 D 确认。
7. 统一处理查询不到、字段错误和内部异常，保证返回 API 合同规定的错误格式。
8. 为商品事实过滤、证据关联、空数据和错误场景补充 pytest。

## 验收标准

- 同一商品针对不同需求字段能够返回不同的证据集合或相关度。
- D 可以拿到结构化商品事实和证据，而不需要解析页面文案。
- 所有输出证据都能追溯到稳定 `source_id`，来源为空时不生成事实结论。
- 外部调用均有超时和异常降级；Mock Store 仍可独立运行。
- `PYTHONPATH=backend python -m pytest backend/tests integration-tests -q` 通过。

## 注意事项

C 负责访问和检索，不负责补写 Mock 内容。需要新增字段时先更新 API 合同和 Pydantic 模型，再由 A 按约定填充数据。
