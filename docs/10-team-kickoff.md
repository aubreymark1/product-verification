# 团队启动讲解（15—20 分钟）

## 我们做什么

用户从短视频中选择一个商品，系统识别候选商品，询问使用条件，再把不同类型的证据整理成一句话结论、支持、风险、待确认项和来源。

## 为什么不是某一种商品工具

商品类别不同，用户关心的条件和验真维度也不同。因此页面字段来自 `category-profile`，公共代码不允许写死某个品类。

## 一次用户流程

视频 → 验一验 → 选择对象 → 确认商品 → 动态条件 → 检索证据 → AI 验真 → 展示结果 → 查看来源 → 加入横评。

## 系统怎么组成

前端负责页面和交互，FastAPI 负责接口，Mock Store 读取联调数据，未来再替换为 SQLite、检索服务和 AI 服务。

## Mock 为什么重要

四个人可以先对着稳定字段并行开发，不必等待真实模型或真实数据。Mock 内容明确标注为演示，不是商品事实。

## 四个人负责什么

A 负责视频、选择和 Mock；B 负责条件和结果 UI；C 负责后端、数据库和检索；D 负责 AI、联调和部署。分支与目录详见 `docs/07-team-ownership.md`。

## 数据怎么传

前端通过 `/api` 请求获取视频、候选、品类配置、结果和证据。字段以 API 合同为唯一依据，不能页面各写一套。

## Git 和 AI 的注意点

从 `dev` 创建自己的 feature 分支，小提交、小范围修改；AI 开始前先阅读 README、合同和所有权，不能整体重构或修改他人目录。

## 合并前检查

确认只改授权目录、合同未漂移、前端构建通过、后端测试通过、没有密钥和无关文件，并在个人分支解决冲突。

## 第一阶段完成标准

四个路由可访问，Mock 主流程可操作，动态表单来源于配置，结果能打开证据，前后端可独立启动，测试和构建通过。
